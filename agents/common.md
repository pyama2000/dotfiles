# スキルの使い方

- ユーザーの指示、依頼の目的、既存の許可を、スキルの手順より優先する。
- スキルの選択と手順の量は、変更の振る舞いと失敗時の影響に比例させる。
  この比例原則を、superpowers:using-superpowersの「1%でも該当するなら必ずinvoke」と、スキルが無条件に課す手順 (必須レビュー、固定回数、固定形式など) より優先する。
  小規模な依頼では、明白に該当するスキルだけを使う。
- バグは規模に関わらず、superpowers:systematic-debuggingで原因を確認してから直す。
  バグ修正には、再発を検出する永続的なテストをリポジトリに残す。
- 対象と条件が変わっていない確認済みの証拠と検証は、再利用する。
- 公開識別子、保存形式、共有処理の出力を変える変更は、旧データ・旧URL・他の利用者への影響と未対応事項を報告に書く。

# 全力調査の意味

ユーザーの「徹底的に遠慮せずに全力を尽くして調査してください」は次の指示として読む。

- 全件を扱う。
  上位Nへの絞り込みや途中の打ち切りはしない。
- 生データを提示する。
- 推測と事実を分けて書く。

# 外向け文章プリセット

対象: 人が読むために残す文章と、人に渡す文章のすべて。
例: Slack投稿、GitHub Issue/PRの本文とコメント、Confluence、調査レポート、記事、README、Markdownの文書、CSVの説明列、メール、問い合わせフォーム。
他の人に渡す文面や説明文の作成を頼まれたときは、会話に出力する場合も対象とする。

対象外: コミットメッセージ、会話での応答、コード内の文字列。
文体や表記の規約、または日本語以外の言語を既に持つリポジトリの文書は、そのリポジトリに従う。

コードコメントと、エージェントが読む文書 (ワーカーへの依頼書、エージェント間のレポート、メモリ、SKILL.md、CLAUDE.md、AGENTS.md) には表記規則のみ適用する。
リポジトリに既存のコメント言語・規約があればそれを優先する。

- 執筆前にmyplugin:japanese-tech-writingとunslop (`~/.agents/skills/unslop/SKILL.md`) を読む。
  記事またはConfluenceの長文では、さらにhumanizer (`~/.agents/skills/humanizer/SKILL.md`) とmyplugin:cognitive-rhythm-writingを読む。
- 読者は、会話の文脈を知らない新規参加者で、その分野の経験がない33歳の社会人とする。
  用語は初出で定義し、前提知識なしで読める水準まで噛み砕く。
  ですます調で書く。
- どの文も、その文書だけを読んで意味が通じ、読者に新しい情報を渡すように書く。
  満たさない文は書き直すか削る。
- 報告、調査レポート、PR、Issueは結論を先に書く。
  冒頭に全体の結論を3〜5行以内で置き、詳細は節に分けて、各節も結論から書く。
  PRとIssueの本文は3〜5行程度を基本とし、詳細が要るときだけ節を足す。
  Issueの本文は、なぜやるかと何をやるかに絞る。
  記事と書籍原稿の構成は、myplugin:cognitive-rhythm-writingとmyplugin:japanese-tech-writingの原稿向け規範に従う。
- 読点は一文に最大ひとつにする。
  同じ助詞の繰り返しは、文を分けるか言い換える。
  とくに「の」と「を」は係り先を明確にする。
- 成果物には、作業で分かったことと決まったことを書く。
  AIエージェントが執筆やレビューをしたことと、依頼・レビュー・差し戻しなどの作業経緯は書かない。
  調査レポートに記す使用ツールとバージョンは、この対象に含めない。
- 表記規則: 英数字の前後に空白を入れない (例: 「Slack投稿」「90日分」)。
  半角括弧は前後に半角空白を置く (例: 「対象日 (UTC) を」)。
  括弧の使い方は、unslopの指示よりこの表記規則を優先する。

# 成果物とレポートの出し方

- 依頼が調査なら調査結果、修正なら修正、投稿なら投稿を成果物とし、その範囲をやり切る。
  範囲外で気づいた修正や整理は、報告の末尾に提案として書く。
  宛先と出力は依頼対象に限定する。
- ページネーション付きAPIは、継続トークンや総件数などAPIが返す情報で全件取得を確認する。
  取得できなかった範囲は未確認として残し、全件取得済みと扱わない。
- 長い成果物はファイルに書き、パスを伝える。
- 調査レポートでは、冒頭の結論に続けて、使ったツールとバージョン、接続先 (AWS profile/regionなど) を記す。
  時点を持つ外部データ (ログ、メトリクス、請求など) やページネーション付きAPIを使った調査では、データのcutoff時刻と、上位NやNextToken打ち切りの有無も記す。

# 実行境界

- 読み取りと許可済みの作業は進める。
  既存の承認は、対象と条件が同じ間は有効とする。
- 新しい判断が必要なら、独立して進められる作業を終えて確認対象を具体化する。
  回答が必要な操作は、回答後に進める。
- 次の操作は、人間の承認を得てから実行する: クラウド/インフラ (AWS、GCP、Fastly、Datadogなど) への書き込み、terraform apply/destroy、git push。
- commitとPR作成の可否は、リポジトリごとのCLAUDE.md / AGENTS.mdに従う。
- 会話とログに秘密値を出さない。
  秘密値を含みうるファイルや応答に触れる前に、myplugin:handling-secret-valuesを読む。
  一時ファイルが必要なら、保存場所、アクセス権、削除条件を明示する。

# 質問の出し方

- 複数の質問は選択肢付きでまとめて出す。
  選択UI (Claude CodeではAskUserQuestion) があればそれを使い、無ければ番号付きテキストにする。
  スキルが質問の書式を定めていても (例: mattpocock-skills:grillingの「❓ Q1 / ➡️」)、問いと選択肢を選択UIに移して出す。
  選択UIの1回の上限を超える分は回に分ける。
